Cómo automatizar tu blog con IA y GitHub Actions

Tareas programadas que actualizan tu sitio solas: portada diaria, sitemap, revisión de enlaces y publicación. Te explico cómo funcionan y qué automatizar primero.

Por César Alessandro Zavala25 de noviembre de 20266 min de lectura

Publicar contenido con constancia es de lo más difícil para un negocio. Siempre hay algo más urgente. Por eso en mis sitios automaticé todo lo que se repite: la portada del periódico cambia sola cada mañana, el sitemap se actualiza cuando hay páginas nuevas y los artículos se regeneran con la plantilla al publicar. En esta guía te explico cómo funciona esa automatización con GitHub Actions y dónde entra la inteligencia artificial.

Qué es GitHub Actions

GitHub Actions es una función de GitHub que ejecuta tareas automáticamente en servidores de GitHub. Esas tareas se llaman workflows y se activan por eventos:

  • Cuando subes un cambio a una rama.
  • A una hora programada, por ejemplo, todos los días a las 6 de la mañana.
  • Cuando alguien abre un pull request.
  • Manualmente, con un botón.

Un workflow puede hacer casi cualquier cosa que harías en una terminal: ejecutar un script, generar páginas, revisar errores y guardar los resultados en tu repositorio. Y si tu repositorio está conectado a tu hosting, esos resultados se publican solos. Si todavía no tienes ese flujo, empieza por cómo publicar tu sitio con GitHub y Hostinger.

Cómo se ve un workflow

Los workflows se escriben en archivos de texto dentro de la carpeta .github/workflows de tu repositorio. Un ejemplo simplificado que se ejecuta cada mañana:

name: Portada diaria
on:
  schedule:
    - cron: "7 12 * * *"
  workflow_dispatch:
jobs:
  portada:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: python3 scripts/portada_del_dia.py
      - run: |
          git config user.name "bot"
          git config user.email "bot@users.noreply.github.com"
          git add index.html
          git commit -m "Portada del día" || echo "Sin cambios"
          git push

La línea cron define el horario. Está en hora UTC, así que hay que convertirla: las 12:07 UTC son las 6:07 de la mañana en el centro de México. La línea workflow_dispatch agrega un botón para ejecutarlo manualmente cuando quieras.

Qué automatizar primero

No empieces por lo más complejo. Estas son las automatizaciones que más valor dan con menos riesgo:

1. Regenerar el sitio con la plantilla

Si usas un generador, el workflow puede ejecutarlo cada vez que agregas o cambias un artículo. Así nunca se te olvida actualizar el índice del blog, las tarjetas de artículos relacionados o el sitemap.

2. Actualizar el sitemap

Cada página nueva debe estar en el sitemap. Un script que recorre las carpetas de tu sitio y escribe el archivo sitemap.xml elimina un olvido muy común. Te explico el archivo en cómo crear un sitemap y robots.txt.

3. Revisar enlaces rotos e imágenes

Un workflow puede revisar que todos los enlaces internos apunten a páginas que existen y que todas las imágenes estén en su lugar. Si encuentra un error, falla y te avisa antes de publicar.

4. Cambiar contenido destacado por fecha

En El Diario de Tamaulipas, un script elige cada mañana las noticias más importantes del día anterior y las coloca en la portada. Esto mantiene el sitio fresco aunque nadie lo toque. Para un negocio, podría ser mostrar la promoción del día o el artículo más reciente.

5. Validaciones de calidad

Antes de aceptar un cambio, un workflow puede comprobar que cada artículo tenga título, descripción, imagen y un mínimo de palabras. Es una red de seguridad muy útil cuando publicas en volumen.

Dónde entra la inteligencia artificial

Hay dos formas de combinar IA con automatización, y conviene distinguirlas:

IA que prepara, humano que aprueba

La IA investiga, redacta borradores o genera páginas, pero los cambios llegan como un pull request que tú revisas antes de publicar. Es el modelo que recomiendo para la mayoría de los negocios y el que uso para publicar decenas de blogs en un día con IA. La velocidad viene de la IA; la responsabilidad sigue siendo tuya.

IA dentro del workflow

También se puede llamar a una API de IA dentro de un workflow para que, por ejemplo, genere un resumen o clasifique artículos automáticamente. Es potente, pero tiene riesgos: si publicas sin revisión, un error o una información incorrecta llega directo a tu sitio. Si lo haces, limita la IA a tareas de bajo riesgo, como sugerir etiquetas, y mantén la revisión humana para el contenido.

Las claves de API van en secretos

Si tu workflow usa una API, nunca escribas la clave en el archivo. GitHub tiene una sección de secrets en la configuración del repositorio donde guardas las claves de forma cifrada, y el workflow las lee sin que queden expuestas.

Cómo diseñar tu automatización

Antes de escribir código, responde:

  • ¿Qué tarea repito cada semana?
  • ¿Qué la dispara: una hora, un cambio o una acción manual?
  • ¿Qué archivos modifica?
  • ¿Qué pasa si falla? ¿Cómo me entero?
  • ¿Necesita revisión humana antes de publicarse?

Con esas respuestas, puedes pedirle a la IA que te escriba el script y el workflow. Pídele también que explique cada línea para que puedas mantenerlo.

Buenas prácticas

  • Empieza con ejecución manual: prueba el workflow con el botón antes de programarlo.
  • Hazlo idempotente: que ejecutarlo dos veces no duplique nada. Por ejemplo, que la portada reemplace la sección anterior en lugar de agregar otra.
  • Usa marcadores en el HTML: comentarios como inicio y fin de sección permiten que el script sepa exactamente qué reemplazar sin tocar el resto.
  • Deja una opción para intervenir: un archivo de configuración donde puedas fijar manualmente el contenido destacado si un día quieres algo especial.
  • Revisa el historial: cada ejecución deja un registro; échale un ojo de vez en cuando.
  • No agregues archivos temporales al repositorio: usa .gitignore para carpetas como las de caché de Python.

Límites y costos

GitHub Actions incluye minutos gratuitos cada mes que alcanzan de sobra para sitios pequeños y medianos. Las tareas programadas pueden retrasarse algunos minutos en horas de mucha demanda, así que no las uses para algo que deba ocurrir al segundo exacto.

Un ejemplo de automatización por etapas

Para un negocio que publica un artículo a la semana, un camino razonable sería:

  • Mes 1: un workflow que regenera el sitio y el sitemap cada vez que se agrega un artículo.
  • Mes 2: validaciones automáticas de enlaces, imágenes y metadatos antes de publicar.
  • Mes 3: un workflow programado que destaca en la portada el artículo más reciente o la promoción vigente.
  • Mes 4: un agente de IA que prepara borradores de artículos en una rama y abre un pull request para revisión.

Cada etapa se apoya en la anterior. Si una automatización falla, sabes exactamente cuál fue porque las agregaste una por una. Y en cada etapa sigues teniendo el control de lo que se publica.

Qué no automatizar

Hay decisiones que conviene mantener manuales: publicar precios o promociones nuevas, responder a clientes con información sensible, cambiar textos legales o políticas, y cualquier contenido sobre temas delicados. La automatización es excelente para tareas repetitivas y verificables; las decisiones con consecuencias deben pasar por una persona.

Preguntas frecuentes

¿Necesito saber programar?

Ayuda entender lo básico, pero puedes pedirle a la IA el script y el workflow con una descripción clara de lo que quieres. Lo importante es probar y entender qué hace.

¿Funciona con WordPress?

GitHub Actions trabaja con tu repositorio. Funciona mejor con sitios estáticos. En WordPress se usan otras herramientas de automatización.

¿Qué pasa si el workflow falla?

GitHub te envía un aviso por correo y el sitio se queda como estaba. Por eso conviene que las validaciones se ejecuten antes de publicar.

Conclusión

Automatizar tu blog no significa dejarlo en piloto automático sin control. Significa que las tareas repetitivas se hacen solas y tú dedicas tu tiempo a lo que importa: decidir qué publicar y revisar que sea bueno. Empieza con una sola automatización, la del sitemap o la portada, y ve sumando.
