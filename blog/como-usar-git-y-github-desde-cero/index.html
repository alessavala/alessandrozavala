Cómo usar Git y GitHub desde cero (para no programadores)

Qué son Git y GitHub, para qué sirven aunque no seas programador y los comandos básicos que necesitas para guardar y publicar tu sitio web.

Por César Alessandro Zavala25 de noviembre de 20266 min de lectura

Git y GitHub suenan a cosas de programadores, pero hoy son útiles para cualquier persona que tenga un sitio web, sobre todo si trabajas con inteligencia artificial. Mis tres sitios viven en GitHub y cada cambio, hecho por mí o por la IA, queda registrado. En esta guía te explico qué son, para qué sirven y cómo empezar sin miedo.

Qué es Git

Git es un programa que guarda el historial de cambios de una carpeta. Cada vez que terminas un cambio, tomas una "foto" de cómo están tus archivos. A esa foto se le llama commit. Si algo sale mal después, puedes regresar a cualquier foto anterior.

Piensa en el historial de versiones de un documento en línea, pero para todos los archivos de tu sitio y con mucho más control.

Qué es GitHub

GitHub es un servicio en internet donde guardas tus carpetas con Git, llamadas repositorios. Sirve para:

  • Tener un respaldo en la nube.
  • Trabajar en equipo sobre los mismos archivos.
  • Conectar tu sitio con tu hosting para que se publique solo.
  • Dejar que herramientas de IA trabajen sobre tu proyecto y te propongan cambios.

Git es la herramienta; GitHub es el lugar donde guardas y compartes lo que hiciste con ella.

Los conceptos clave

  • Repositorio: la carpeta de tu proyecto con todo su historial.
  • Commit: una versión guardada con una descripción de lo que cambió.
  • Rama (branch): una línea paralela de trabajo. La principal suele llamarse main.
  • Push: subir tus commits a GitHub.
  • Pull: bajar a tu computadora los cambios que están en GitHub.
  • Clone: copiar un repositorio de GitHub a tu computadora por primera vez.
  • Pull request: una solicitud para integrar los cambios de una rama en otra, que se puede revisar antes de aceptarla.
  • Merge: fusionar los cambios de una rama con otra.

Cómo empezar sin terminal

Si los comandos te dan miedo, empieza con la aplicación GitHub Desktop. Es gratuita y te permite hacer todo con botones:

  • Crear un repositorio desde una carpeta.
  • Ver qué archivos cambiaron.
  • Escribir la descripción del cambio y hacer commit.
  • Subir los cambios con un botón.

Cuando te sientas cómodo, los comandos te darán más velocidad.

Los comandos básicos

Si prefieres la terminal, estos son los que vas a usar el 90% del tiempo:

git clone https://github.com/tu-usuario/tu-sitio.git
git status
git add .
git commit -m "Cambio el horario de atención"
git push
git pull
  • clone descarga el repositorio la primera vez.
  • status te dice qué archivos cambiaron.
  • add prepara los cambios para guardarlos. El punto significa "todos".
  • commit guarda la versión con una descripción.
  • push sube los cambios a GitHub.
  • pull baja los cambios que hizo alguien más.

Escribe buenas descripciones

"Cambios" no sirve. "Actualizo precios del menú de diciembre" sí. Cuando busques en el historial dentro de seis meses, vas a agradecer haber sido claro.

Trabajar con ramas

Las ramas te permiten probar cambios sin afectar tu sitio publicado:

git checkout -b nueva-seccion-promociones

Trabajas en esa rama, haces tus commits y la subes a GitHub. Luego, en la página del repositorio, abres un pull request hacia main. Revisas los cambios, y si todo está bien, los fusionas. Si tu hosting publica la rama main, sólo en ese momento el cambio llega a tu sitio.

Este flujo es especialmente útil cuando la IA hace cambios: la IA trabaja en una rama, tú revisas el pull request y decides si se publica.

El archivo .gitignore

Hay archivos que no deben subirse a GitHub: contraseñas, configuraciones locales, carpetas temporales. Para eso existe el archivo .gitignore, donde escribes qué archivos o carpetas debe ignorar Git:

.env
config-local.php
__pycache__/
.DS_Store

Una lección importante

Si subes por error un archivo con contraseñas a un repositorio, borrarlo después no basta: sigue en el historial. Lo correcto es cambiar las contraseñas de inmediato y, si el repositorio es público, hacerlo privado. Es un error más común de lo que crees, sobre todo al migrar sitios de WordPress, cuyo archivo wp-config.php contiene la contraseña de la base de datos.

Público o privado

  • Público: cualquiera puede ver tu código. Útil para proyectos abiertos o portafolios.
  • Privado: sólo tú y las personas que invites. Recomendable para sitios de negocio.

Puedes cambiar la visibilidad en la configuración del repositorio cuando quieras.

Cómo regresar a una versión anterior

Uno de los superpoderes de Git es deshacer. Si publicaste algo que rompió tu sitio, puedes revertir ese commit y el sitio regresa a como estaba. En GitHub Desktop es un clic derecho sobre el commit y "Revert". En la terminal:

git revert [identificador-del-commit]
git push

Revertir crea un nuevo commit que deshace el anterior, así el historial queda completo.

Errores comunes de principiante

  • Trabajar sin hacer pull primero y encontrarte con conflictos.
  • Hacer un solo commit gigante con todo el trabajo de una semana.
  • Subir contraseñas o archivos pesados innecesarios.
  • Trabajar directamente en la rama que se publica cuando el sitio es importante.
  • No escribir descripciones claras.

Qué es un conflicto

Ocurre cuando dos personas cambian la misma línea del mismo archivo. Git no sabe cuál versión conservar y te pide elegir. Se ve intimidante, pero sólo tienes que abrir el archivo, decidir qué texto queda y hacer commit.

Cómo encaja con la IA

Los agentes de programación con IA trabajan muy bien con Git: clonan tu repositorio, crean una rama, hacen los cambios, los prueban y abren un pull request. Tú sólo revisas y apruebas. Es el flujo que uso para publicar decenas de blogs en un día con IA y que te explico con el hosting en cómo publicar tu sitio con GitHub y Hostinger.

Un flujo de trabajo diario sencillo

Si eres la única persona que trabaja en tu sitio, este flujo es suficiente:

  • Al empezar el día, haz pull para tener la versión más reciente.
  • Haz un cambio pequeño y revísalo en tu computadora.
  • Haz commit con una descripción clara.
  • Repite con el siguiente cambio.
  • Al terminar, haz push para subir todo a GitHub.

Si trabajas con más personas o con una herramienta de IA, agrega las ramas y los pull requests para que nadie publique algo sin revisión. Lo importante es la constancia: commits pequeños y frecuentes son mucho más fáciles de entender y de revertir que un cambio enorme cada mes.

Cómo ver el historial

En la página de tu repositorio en GitHub, la sección de commits muestra todos los cambios con fecha, autor y descripción. Puedes dar clic en cualquiera para ver exactamente qué líneas cambiaron: en verde lo que se agregó y en rojo lo que se quitó. Es muy útil para responder preguntas como "¿cuándo cambiamos el precio?" o "¿quién quitó esa sección?".

Cómo pedir ayuda a la IA con Git

Si un comando de Git te da un mensaje que no entiendes, copia el mensaje completo y pídele a la IA que te explique qué significa y qué opciones tienes antes de ejecutar cualquier cosa. Algunos comandos pueden borrar trabajo, así que pide siempre la opción más segura.

Preguntas frecuentes

¿GitHub es gratis?

Sí, para la mayoría de los usos personales y de pequeños negocios, incluidos repositorios privados.

¿Git sirve sólo para código?

Sirve para cualquier archivo de texto: páginas web, documentación, contenido de blog. Para archivos muy pesados, como videos, no es la mejor opción.

¿Puedo romper mi sitio con Git?

Puedes publicar un cambio que lo rompa, pero Git te permite regresar a la versión anterior en segundos. Es mucho más seguro que subir archivos a mano.

Conclusión

Git y GitHub son el seguro de vida de tu sitio web. Te dan historial, respaldo, trabajo en equipo y la base para automatizar con inteligencia artificial. No necesitas ser programador: con seis comandos o una aplicación con botones ya tienes todo lo que necesitas para empezar.
