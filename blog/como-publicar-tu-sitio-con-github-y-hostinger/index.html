Cómo publicar tu sitio con GitHub y Hostinger (despliegue automático)

Conecta tu repositorio de GitHub con Hostinger para que cada cambio se publique solo. Te explico el flujo que uso en mis sitios, paso a paso y con sus errores comunes.

Por César Alessandro Zavala25 de noviembre de 20266 min de lectura

Durante años, publicar un cambio en una página web significaba entrar al administrador de archivos del hosting, buscar el archivo correcto, subirlo y rezar para no romper nada. Hoy mis tres sitios se publican solos: hago un cambio, lo guardo en GitHub y en unos minutos está en línea. En esta guía te explico cómo montar ese mismo flujo con Hostinger.

Qué vas a lograr

Al terminar tendrás:

  • Tu sitio guardado en un repositorio de GitHub, con historial de todos los cambios.
  • Hostinger conectado a ese repositorio.
  • Publicación automática cada vez que subas cambios a la rama principal.
  • La posibilidad de regresar a cualquier versión anterior si algo sale mal.

Este flujo funciona para sitios estáticos: archivos HTML, CSS, JavaScript e imágenes. Si tu sitio es WordPress, el proceso es distinto porque depende de una base de datos.

Por qué vale la pena

  • Historial completo: cada cambio queda registrado con fecha, autor y descripción.
  • Menos errores: ya no subes archivos a mano.
  • Trabajo en equipo: varias personas pueden colaborar sin pisarse.
  • Automatización: puedes conectar herramientas, incluida la IA, que publiquen por ti.
  • Respaldo: si tu hosting falla, tu sitio completo sigue en GitHub.

Lo que necesitas antes de empezar

  • Una cuenta de GitHub, gratuita.
  • Un plan de hosting en Hostinger con acceso a hPanel.
  • Tu dominio apuntando a Hostinger.
  • Los archivos de tu sitio en una carpeta, con un index.html en la raíz.

Si nunca has usado Git, lee primero cómo usar Git y GitHub desde cero. Te tomará media hora entender lo básico.

Paso 1: crea el repositorio

En GitHub, da clic en "New repository". Ponle un nombre claro, como el de tu dominio. Elige si será público o privado.

Aquí va un consejo importante: si tu sitio tiene cualquier archivo con contraseñas, claves o datos sensibles, el repositorio debe ser privado, y aun así esos archivos no deberían estar ahí. Un repositorio público es visible para cualquier persona en internet, incluidos programas que buscan contraseñas expuestas.

Paso 2: sube tus archivos

Desde tu computadora, dentro de la carpeta del sitio, ejecutas los comandos básicos de Git: iniciar el repositorio, agregar los archivos, hacer el primer commit y subirlo a GitHub. Si prefieres no usar la terminal, puedes arrastrar los archivos a la página del repositorio en GitHub o usar la aplicación GitHub Desktop.

Revisa que en la raíz del repositorio quede el archivo index.html y no una carpeta que lo contenga. Si el index queda dentro de otra carpeta, Hostinger publicará esa carpeta y tu sitio no se verá en la dirección principal.

Paso 3: conecta Hostinger con GitHub

En hPanel busca la sección de Git dentro de las opciones avanzadas de tu sitio. Ahí vas a:

  • Pegar la dirección del repositorio.
  • Indicar la rama que se publicará, normalmente main.
  • Indicar el directorio de destino. Para que el sitio aparezca en tu dominio principal, el destino es la carpeta public_html.

Si el repositorio es privado, Hostinger te dará una clave de despliegue que debes agregar en la configuración del repositorio en GitHub, en la sección de Deploy keys. Esa clave le permite a Hostinger leer el repositorio sin darle acceso a tu cuenta completa.

Un detalle que causa muchos problemas

Hostinger normalmente pide que la carpeta de destino esté vacía la primera vez. Si public_html ya tiene archivos, por ejemplo de un WordPress anterior, el despliegue puede fallar o mezclar archivos viejos con nuevos. Haz un respaldo y vacía la carpeta antes de conectar.

Paso 4: activa el despliegue automático

En la misma sección encontrarás la opción de implementación automática. Hostinger te dará una dirección de webhook. Cópiala y agrégala en GitHub, en la configuración del repositorio, sección Webhooks. Desde ese momento, cada vez que subas cambios a la rama configurada, GitHub avisará a Hostinger y este descargará la nueva versión.

Haz una prueba: cambia un texto pequeño, súbelo y revisa tu sitio en unos minutos. Si el cambio aparece, el flujo está listo.

Paso 5: trabaja con ramas si el sitio es importante

En un sitio que genera clientes no conviene subir cambios directamente a producción. Lo que hago en sitios importantes es:

  • Crear una rama temporal para cada cambio.
  • Hacer el trabajo en esa rama.
  • Abrir una solicitud de cambios, llamada pull request, hacia la rama de producción.
  • Revisar el cambio y, si todo está bien, fusionarlo.

Así, la rama de producción sólo recibe cambios revisados. En el caso de Estudio E-commerce, por ejemplo, la rama de producción es distinta de la de pruebas, y todo pasa por pull request antes de publicarse.

Errores comunes y cómo resolverlos

El sitio sigue mostrando la versión anterior

Casi siempre es caché. Hostinger y su servidor LiteSpeed guardan copias de las páginas para servirlas más rápido. Limpia la caché desde hPanel y revisa en una ventana de incógnito. Si usas un CDN, límpialo también.

Aparece una página de WordPress que no es la mía

Quedó una instalación anterior en el hosting o un archivo index.php con prioridad. Revisa que no haya archivos viejos en public_html y, si había WordPress instalado, desinstálalo desde hPanel.

Error de "conexión no es privada"

El certificado SSL no está activo para tu dominio. Actívalo desde hPanel. Mientras no esté activo, no fuerces la redirección a https en tu archivo .htaccess, porque los visitantes verán una advertencia. Te explico el proceso en cómo activar SSL y HTTPS.

El despliegue falla

Revisa el registro de despliegues en hPanel. Las causas más comunes son una clave de despliegue mal configurada, una rama con nombre distinto o una carpeta de destino que no estaba vacía.

El archivo .htaccess

En hostings con Apache o LiteSpeed, como Hostinger, el archivo .htaccess en la raíz controla reglas importantes: redirecciones 301 de páginas viejas a nuevas, forzar https cuando el certificado ya esté activo, páginas de error personalizadas y reglas de caché. Guárdalo en tu repositorio para que se publique junto con el sitio, y cada vez que lo modifiques, prueba que tu sitio sigue cargando.

Cómo encaja la IA en este flujo

Una vez que tu sitio vive en GitHub, la IA puede trabajar directamente sobre el repositorio: generar páginas nuevas, corregir errores, actualizar el sitemap y preparar un pull request para que tú lo revises. Es exactamente el flujo que uso para publicar decenas de blogs en un día con IA. La clave es que la IA proponga y tú apruebes lo que llega a producción.

Buenas prácticas de seguridad

  • Activa la verificación en dos pasos en GitHub y en Hostinger.
  • No guardes contraseñas en el repositorio. Usa variables de entorno o los secretos del hosting.
  • Si alguna vez subiste una contraseña por error, cámbiala de inmediato: borrar el archivo no la elimina del historial.
  • Revisa quién tiene acceso al repositorio y quita a quien ya no lo necesita.

Preguntas frecuentes

¿Es gratis?

GitHub es gratuito para repositorios públicos y privados con funciones básicas. La conexión con Hostinger está incluida en sus planes de hosting web.

¿Cuánto tarda en publicarse un cambio?

Normalmente unos segundos o pocos minutos después de subirlo. Si no aparece, revisa la caché.

¿Puedo usarlo con varios sitios?

Sí. Cada sitio tiene su repositorio y su conexión. Yo manejo tres sitios así, cada uno con su propio flujo.

Conclusión

Conectar GitHub con tu hosting es de esas mejoras que se hacen una vez y se agradecen siempre. Ganas historial, seguridad, velocidad para publicar y la base para automatizar con inteligencia artificial. Si todavía subes archivos a mano, este es el siguiente paso.
